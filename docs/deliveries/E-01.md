# E-01 — Configuración y API
Objetivo: iniciar FastAPI con configuración explícita validada y responder salud/errores sin revelar información sensible.
Responsable: agente implementador; cierre: Derlis. HARD: E-00 COMPLETED sobre ce7dfa7. CONTRACT: formato /v1 y error code/message/request_id aprobado en arquitectura. EXTERNAL: ninguna cuenta o servicio; paquetes fijados en E-00.
Alcance: factory de aplicación, configuración APP_ENV y CORS_ORIGINS, salud GET /v1/health, request_id generado en servidor, logs JSON limitados a método/estado/identificador, errores JSON, OpenAPI versionado y pruebas HTTP.
Exclusiones: DB, Auth, permisos institucionales, rate limiting, contenido, videos, readiness de servicios externos y despliegue. No endpoints privados en E-01.
Módulos: shared y entrypoint. Archivos: services/api/app/{main,factory}.py; shared/{config,logging}.py; tests/test_api.py; packages/contracts/openapi.json; docs/evidence/E-01; .env.example; README y estado.
Migraciones: N/A sin acceso a datos. Endpoints: GET /v1/health -> 200 {status:ok}; desconocido -> 404 con envelope; método no permitido -> 405. Salud indica proceso/configuración, no conectividad DB.
Permisos: salud pública sin datos personales; CORS limita orígenes de navegador y no sustituye autorización. Docs/OpenAPI HTTP solo en development/test; schema en repo para contrato.
Configuración: APP_ENV obligatorio development/test/production; CORS_ORIGINS obligatorio JSON array no vacío de orígenes explícitos sin wildcard, credenciales, path/query/fragment; production solo HTTPS. No leer .env automáticamente ni imprimir valores inválidos.
Casos: ausencia/valor inválido impide construir app; CORS inválido y wildcard rechazados; production con HTTP rechazado; salud 200 y UUID de servidor; origen permitido pasa preflight; ajeno falla; 404/405 usan envelope; 500 no revela excepción; logs no incluyen URL/query/tokens; documentos HTTP deshabilitados en production; schema exportado coincide con factory.
Evidencias: pytest/Ruff/compileall, schema check, regresión web/CI y diff; logs con commit identificado. Reversión: revertir commit, sin datos/recursos creados. Cierre: DoD y aprobación humana del commit probado.
