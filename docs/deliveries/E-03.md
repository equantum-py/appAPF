# E-03 — Autenticación y autorización
ID: E-03
Nombre: Identidad Supabase JWT y membresías
Objetivo: FastAPI acepta solo JWT válidos del issuer configurado y aplica permisos de DB antes de devolver datos.
Responsable: agente implementador; Derlis cierre.
Dependencias HARD: E-02 COMPLETED. CONTRACT: identidad UUID, espacio personal/institucional, /v1 y envelope aprobado. EXTERNAL: servicio oficial Supabase Auth v2.196.0 efímero en CI, DB dedicada y usuarios sintéticos; no se usan proyectos cloud ajenos. Binding cloud persistente queda para despliegue.
Alcance: ingreso Next.js mediante Supabase SSR browser client, sesión persistida en cookies, consulta a FastAPI con bearer y salida local; ES256/RS256 mediante JWKS remoto fijo; expiración, issuer, audiencia, subject y sesión; actor interno ligado a sub; membresía activa por petición; contexto DB local a transacción; rutas read-only /v1/me, /v1/me/memberships, /v1/organizations/{id}/access y /memberships (ADMIN institucional). No confiar en metadatos de usuario para roles.
Exclusiones: credenciales/passwords gestionadas por API, provisión automática de usuarios, escritura/admin de usuarios E-15, videos, auditoría de negocio E-04, producción y cuentas ajenas.
Módulos afectados: identity, organizations, shared, factory. Archivos: auth_config.py, identity/jwt.py y access.py, organizations/access.py, identity/routes.py; migration0002; tests/auth*.py; OpenAPI y evidencia.
Migraciones: 0002 ajusta lectura por sub firmado y descubrimiento de membresías propias, sin cambiar tablas ni datos históricos. Upgrade/downgrade probados solo DB efímera. RLS confía en contexto asignado por backend; cliente no recibe credenciales SQL.
Endpoints/permisos: me y membresías propias con identidad válida/provisionada; access con membresía activa/propietario personal; listado de membresías institucionales exige ADMIN en esa misma organización. Todo devuelve no-store. Falta config -> 503; credencial inválida ->401; usuario no provisionado o alcance/rol ajeno ->403.
Reglas: key alg/kid verificados, no jku del token, caché JWKS60s/refresco desconocido limitado30s, fallar cerrado sin claves válidas. Audiencia authenticated, role authenticated, is_anonymous=false si presente; session_id/sub UUID y iat/exp requeridos. No se garantiza revocación instantánea por JWKS; desactivar membresía bloquea en próxima petición. HS256 no aceptado; si proyecto solo HS256 hay que acordar adaptación/verificación online sin rotar automáticamente.
Pruebas: JWT firma incorrecta, expiry, nbf/iat futuro, issuer/aud incorrecto, none/HS256, kid desconocido, JWK no aceptable, claims ausentes/UUID inválido, usuario anónimo/service_role, metadatos falsos ignorados; JWKS cae/refresca/rota; PostgreSQL runtime sin bypass/propiedad; tenant, membresía desactivada, personal ajeno, rol admin ajeno, parámetros org inválidos y contexto sin fuga tras reutilizar conexión; regresión/migración/OpenAPI.
Criterios de aceptación: pruebas automatizadas PASS + prueba de token realmente emitido por servicio oficial Supabase Auth aislado y recorrido de autenticación documentado. No llamar tokens fixture Supabase real; no COMPLETED con live NOT_RUN.
Evidencias: commit, CI, JWT efímeros no persistidos, JUnit; live y navegador NOT_RUN hasta CI. Riesgos: el proxy de CI no valida claves de gateway cloud; salida local no invalida inmediatamente JWT ya emitidos; recurso cloud persistente no provisionado. Reversión: revertir commit y downgrade0002 únicamente test sin datos reales.
Condición de cierre: DoD, recurso externo satisfecho y aprobación humana. Estado: IN_PROGRESS; pendiente evidencia CI y aprobación humana.
